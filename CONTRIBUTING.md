# Code Contributor Guidelines

Welcome to the project! Please follow these guidelines when contributing code or documentation.

## Branch Naming Conventions
- `docs/` - For documentation additions and updates (e.g., `docs/api-reference`)
- `feature/` - For new application functionality
- `fix/` - For bug fixes and security patches

## Pull Request Process
1. Ensure your code or documentation changes are well-scoped.
2. Link your issue in the Pull Request body using `Closes #<issue_number>` (e.g., `Closes #4`).
3. Assign a teammate as a **Reviewer**.

## Code Review Guidelines
- Reviewers will leave line-by-line comments and inline suggestions.
- Authors must accept suggestions via **Commit suggestion** and click **Resolve conversation**.
- Every PR requires an explicit **Approval** before merging into `main`.
